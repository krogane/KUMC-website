# 更新・障害対応・引き継ぎ

## 日常の更新

公開原稿を編集 → PRの検証 → mainへ反映 → Build and deploy Pagesの成功 → 本番確認。main更新時と6時間ごと（UTC 00/06/12/18時17分）のworkflowでRSSも更新します。スケジュールは遅延・停止することがあり、リアルタイム保証ではありません。

GitHubの公開リポジトリでは60日間活動がない場合にスケジュールが無効になることがあります。Actionsの有効状態を月次確認し、停止時は原因を確認して再有効化します。[GitHub schedule仕様](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## フィード障害

1. Actionsの実行サマリーの警告と、`.cache/feeds.json` の `fetchedAt` を確認する。取得日時は画面には表示しない。
2. 公式RSSが取得可能か、配信仕様・ホスト・証明書に変更がないか確認する。失敗した本文や内部情報をログへそのまま貼らない。
3. `npm run feeds` で取得を再試行する。各ソース独立で、失敗しても正常データを空に上書きしない。
4. `.cache/feeds.json` は前回正常値。GitHubの `feed-snapshot` artifactは90日保持し、次回へ引き継ぐ。消失時は `src/data/feed-fallback.json`、それもなければ元サイトへのリンクだけを表示する。
5. 同梱スナップショットを更新する場合は、取得成功・内容・公開範囲を確認してから `.cache/feeds.json` の確認済み内容を反映する。取得失敗時の値を「最新」として上書きしない。

48時間以上経過した一覧には元サイトの確認を促します。ビルド時とブラウザ表示時に判定するため、定期workflowが止まっても案内が出ます。RSSは新規公開順であり、既存作品の更新検知を保証しません。

## 記事の取り下げ・リンク切れ

`src/data/feed-exclusions.json` の該当ソース配列へ正規URLを追加し、ビルド・公開します。除外は新規取得とキャッシュ双方へ適用します。取り下げ理由や個人情報はこのJSONへ書きません。元データの非公開化だけでは古いスナップショットに残る場合があるので、緊急時は必ず除外します。

作品配布終了時は `status: 公開終了`、`downloads: []`。関連案内も修正します。外部リンクを確認できないだけで配布終了と断定せず、確認日と実状を調べます。サイト独自原稿を非公開にしたい場合は `draft: true` で再公開しますが、公開済みGit履歴・検索キャッシュから消えることまでは保証しません。

## 公開失敗・復旧

失敗したbuildはdeployへ進まないため、直前の公開サイトはそのまま残ります。Actionsログで型・原稿・テスト・GA設定・Pages設定のどこが失敗したかを確認します。警告を消すためにテストや権限検査を無効にしません。

コードを戻す場合は、既知の正常コミットとの差分を確認し、原因の変更を **git revert** するPRを作成 → CI → mainへ反映します。これにより正常コードを検証して再デプロイできます。履歴を強制書き換えしません。依存関係のlockfileも同じ状態へ戻します。外部フィードは再取得されるため、完全に同じ表示が必要な復旧では確認済みスナップショットを明示的に復元してください。

GitHub上で正常runを再実行しても現在の外部RSS・失効したartifactの影響があるため、常に全く同じ成果物とは限りません。緊急停止は `PAGES_ENABLED=false` で新規デプロイを止めます（既存公開サイトは消えません）。既存サイトを非公開にする操作はPages設定で別途行います。

## 月次・年度替わり

月次：連絡先／入会導線、外部配布先、RSS成功日時、X表示、GA拒否／撤回、Actionsの有効状態、依存更新・audit、ドメイン期限を確認します。

年度替わり：会則・受入条件・活動状況、管理担当、GitHub／GA4／Search Console／DNSの権限、更新費用の管理、MFA・復旧連絡先を確認します。担当交代は権限追加 → 新担当の操作確認 → 旧担当の不要権限削除の順で行います。

廃止・移転時は不要なDNS（A/AAAA/CNAME）を先に整理し、古いPages登録・サイトを解除して、ドメイン乗っ取りの余地を残しません。原本・コード・必要な正常スナップショットを管理された保存先へ引き継ぎます。
